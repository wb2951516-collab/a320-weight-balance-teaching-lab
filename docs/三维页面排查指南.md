## 一、先分清三种"卡住"，症状完全不同

| 症状 | 界面表现 | 说明 |
|---|---|---|
| **A. 能开，永远停在「正在加载模型…」且无任何提示** | 三维区空白 | 脚本一行都没执行（被整体拦截） |
| **B. 同上，但有红框提示** | 给了具体错误与建议 | 脚本跑了，是加载失败 |
| **C. 浏览器报「拒绝连接」** | 白底错误页 | 服务没起来 |

`web/index.html` 已内置兜底诊断：A 类也会给出提示（由一段**经典脚本**负责，
它不受模块拦截影响）。**单文件版不存在 A 类问题。**

## 二、按嫌疑度排列的原因（均经实测确认）

### 1. 用 `file://` 打开 `web/index.html` ← 第一嫌疑

**原理**：该页用 ES 模块加载 three.js、用 `fetch` 读 GLB。浏览器对 `file://` 下的
模块加载与 fetch **一律按跨域拦截**，脚本一行都不会执行。

**识别**：地址栏以 `file:///` 开头。

**解决**：① 改开单文件版（见第零节）；② 用 `启动预览.cmd`；③ 手工起服务。

### 2. `.ps1` 双击没反应 ← 本轮实测确认，本机特有

实测本机 `.ps1` 的文件关联被指向了 **应用商店 AppX 程序**
（`HKCU\...\FileExts\.ps1\UserChoice` = `AppXxf01pj590w7z9mxmyv3nx0a9ewj3e51g`），
**双击不会执行脚本**。而执行策略是 `RemoteSigned`，本地脚本本可运行——所以问题不在策略，在关联。

**解决**：改用 `启动预览.cmd`（`.cmd` 双击走的是正常命令解释器，不受此影响）。

### 3. 端口被占用，服务起来即退出 ← 本轮实际发生过

上一版预览服务没关，仍监听 8777，新起的服务报 `Address already in use` 后立刻退出，
窗口一闪而过，表现为"点了没反应"。

**排查**：
```powershell
Get-NetTCPConnection -LocalPort 8777 -ErrorAction SilentlyContinue |
  ForEach-Object { Get-Process -Id $_.OwningProcess }
```
**解决**：关掉旧窗口，或换端口——`启动预览.cmd` 会**自动在 8777~8786 里挑一个空闲端口**，
并在窗口里打印实际使用的地址。

### 4. `.cmd` 用了 LF 换行 ← 本轮实测确认，隐蔽性极强

Windows 批处理**必须用 CRLF 换行**；LF-only 会让 `for (...)` / `if (...) else (...)` 这类
块结构解析失败，表现为双击毫无反应。用字节级检查即可确认：

```powershell
$b=[IO.File]::ReadAllBytes("…\启动预览.cmd")
[regex]::Matches([Text.Encoding]::ASCII.GetString($b),"`r`n").Count   # 应等于总行数
[regex]::Matches([Text.Encoding]::ASCII.GetString($b),"(?<!`r)`n").Count  # 应为 0
```

另：`.cmd` **必须保持纯 ASCII**。cmd.exe 按 OEM 代码页（简中 GBK）读 .cmd 文件而非 UTF-8，
写入中文可能被错误解码而破坏解析。因此该脚本**刻意不含中文**，路径靠 `%~dp0` 运行时获取。

### 5. `vendor\three` 目录联接（junction）失效

`web/vendor/three` 是指向 `D:\three.js` 的 junction，不是实体拷贝。
拷贝文件夹到别的机器、或 D 盘那份被移动，链接即失效。

**解决**：重建联接，或做实体拷贝（**对外分发必须实体拷贝**）。
**单文件版不受影响**——three.js 已内联。

### 6. 浏览器 WebGL 不可用

常见于远程桌面 / 虚拟机，或关了硬件加速。页面会显示「WebGL 初始化失败」（属 B 类，不是静默卡住）。
检查：`chrome://gpu`。远程桌面下可加参数 `--enable-unsafe-swiftshader`（软件渲染，慢但能用）。

### 7. Draco 解码器缺失

只有当模型是 `teach_model_draco.glb` 时才需要解码器。
**当前交付的 `teach_model.glb` 是 dedup 版，不含 Draco，不需要解码器。**

### 8. 浏览器缓存了旧版本

改过页面或重新导出模型后仍是旧表现 → `Ctrl + F5`。

## 三、三步定位法

1. **看地址栏**：`file://` → 直接改开单文件版，不用往下查。
2. **看页面提示**：按提示里的分类对症处理（第 2~5 条）。
3. **按 F12 看 Console**：提示是概括性的，Console 才是原始报错。
   - `Failed to fetch dynamically imported module` → 第 5 条
   - `CORS policy` → 第 1 条
   - `Invalid URL` → 出现在自打包版本里，说明 `import.meta.url` 在 IIFE 下为空
     （本仓库已在构建时用 `document.baseURI` 替换，不应再出现）

## 四、页面内置的自检能力

HUD 左上角「自检」行显示：
`源网格 697 · 几何签名 52 · 实例网格(draw) 73 · 实例 697 · 组 33 · 标注 40 (troika-sdf)`

这些数字正常出现 = 模型、元数据、实例化、面板全部就绪，问题只在渲染或交互层。

URL 参数可直达指定状态，便于远程复现：
`?t=100`（全拆）`?src=AC_ROOT`（只教学装配体）`?src=AIRCRAFT_ROOT`（只外观壳）
`?labels=1`（开标注）`?view=cargo`（货物视角）`?hide=ANNO_UI`
