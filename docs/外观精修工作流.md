## 一、唯一真源与入口

```
scripts/a320_data.py          ← 机型数据唯一真源（长度/直径/弦长/后掠/上反/座位/货舱…）
scripts/stage2_shape.py       ← 机翼/平尾/垂尾梯形面、186Y 补排、地板延长
scripts/stage2_refine.py      ← 本轮新增：机体/短舱/翼型/门窗/腰线/油箱的精修
scripts/stage1_export.py      ← ★ 唯一入口：读源 .blend（只读）→ 调 stage2 → 注入契约 → 导出
tools/optimize_glb.mjs        ← dedup + prune（5067 KB → 约 1.5 MB，extras 零丢失）
tools/audit_explode.mjs       ← 拆解三条硬约束（地面/重叠/可见性）
tools/build_standalone.mjs    ← 打包为双击即开的单文件 HTML
tools/render_check.mjs        ← CDP 无头渲染自检（本项目的标准验证手段）
tools/dump_group.mjs          ← 按组列出零件名字/顶点数/世界 AABB；`--all` 按 X 排序判机头朝向
```

**几何必须在脚本里生成，不能在 Blender 里手改。** 手改只落在当前会话的场景里，
下次跑 `stage1_export.py` 会从源 .blend 重来、全部丢失。
Blender MCP 的正确用法是**交互式试形 + 看视口产出**，结论落回脚本。

## 三、复发性坑（★ 每个都实际踩过）

### 1. `%` 不能出现在带格式化的 verbose 串里
```python
verbose("…弦向 28%~68%…" % made)      # TypeError: not enough arguments for format string
verbose("…弦向 28%%~68%%…" % made)    # 正确
```
同一类错误在 `%MAC` 打印（导出脚本）上也犯过一次。**写完必跑一次**，别指望读代码时发现。

### 2. 法线重算用 bmesh，不要用 `bpy.ops`
`bpy.ops.object.mode_set()` 依赖 GUI 上下文，在 **Blender MCP 远程调用**与
**`open_mainfile` 之后同一段代码里继续执行**两种情形下都会抛
`mode_set.poll() 上下文缺失活动物体`。改用：
```python
bm = bmesh.new(); bm.from_mesh(me)
bmesh.ops.recalc_face_normals(bm, faces=bm.faces)
bm.to_mesh(me); bm.free(); me.update()
```

### 3. MCP：`open_mainfile` 与后续 operator 要分两次调用
同一段代码里紧跟其后执行 operator 会失败（上下文还没重建）。分两步即可。

### 4. 同名函数定义两次 → 后者静默覆盖
`stage2_refine.py` 一度有两个 `refine()`，后写的（不含新步骤）覆盖了前一个，
**新写的 `build_doors_windows` / `check_skin_fit` 根本没被调用**。
用 `grep "^def "` 核一遍；入口函数只留一个，放在文件末尾。

### 5. 按名字找 Blender 节点不可靠
`nodes.get("Principled BSDF")` 依赖节点**名字**；原 .blend 里 `M_CockpitGlass` 是早期脚本
建的，节点名不是这个 → `.get()` 返回 None → 颜色根本没写进去 → 风挡渲染成浅灰平板。
**按 `node.type == 'BSDF_PRINCIPLED'` 找，找不到就重建节点树。**

### 6. 分段生成机体时不要加内部端盖
三段（尾锥/筒/机头）在接缝处各加一个人造端盖 → 两个盖子面对面贴合，
接缝那一圈顶点的法线被拉成轴向，渲染出**一道竖向硬边**。
封盖只加在最外两端（尾尖、机头尖）。

### 7. 门窗改为曲板后 draw call 会暴涨 —— 必须共享几何
`panel()` 用世界坐标烘焙，48 扇窗就是 48 份不同顶点数据 → 视图侧按几何签名分桶时
无法合并，draw call 从 69 涨到 **126**。
处置：**同 kind + 同侧 + 同尺寸**的门/窗算一份**局部几何**（`const_r=R_BODY` 等截面、
x 以 0 为中心），各对象只设 `location.x`。实测几何复用 113 → 58 份、draw call 126 → **71**。
（腰线横跨机头锥起点、剖面半径沿长度变化，无法用等截面局部几何，保留单件，只有 2 件。）

### 8. 脱敏门禁会被机器生成的"坐标汤"刷爆
单文件课件内联 base64 后，短规则（两字码 `8L`）必然在几 MB 随机串里被命中：
**332 处命中全是噪声**，把 exit code 打成 1、把真泄漏淹没。
`desensitize_check.py` 现有三类掩码 + 短规则词边界约束：
| 形态 | 例子 | 掩码后 |
|---|---|---|
| `data:...;base64,<长串>` | 单文件课件内联 GLB | 332 → 104 |
| 裸 base64（打包器塞进 JS 字符串） | WASM/字体 | 104 → 2 |
| SVG 路径坐标串 | `M8,8L16,8L24,24L16,24Z` 里的 `8L16` | 2 → **0** |
外加：≤3 字符的 literal 规则加"左侧非字母数字"约束，右侧**允许接数字**（两字码粘航班号 `8L1234` 不能漏）。

## 五、量的取舍

* **整机长**以 `a320_data.LENGTH = 37.57` 为准（机头 +18.785 → 尾端 −18.785）。
* **机身半径**用权威值 `FUS_DIA/2 = 1.975`（不是原模型的 2.000）：舱门/舷窗面板位于

  结果，属可接受的风格化取舍；要改需先改 LOPA 站位表。

## 六、标注层（viewer 侧）的三条约定

1. **恒定屏幕字高**，不按世界尺寸画。
   0.84 m 的文字在 62 m 机位下只有约 11 px 高 —— 这正是"标注偏小看不清"的根因。
   现在 `LABEL_PX = 17`：每条标注按当前机位反算缩放（限幅 0.35~8），
   近处不巨大、远处不消失、拆解拉远也不缩水。

2. **屏幕空间贪心避让，只做显隐不做位移**（`layoutLabels()`）。
   投锚点 → 用"锚点 vs 锚点+相机右/上向量×尺寸"两点投影算**实际像素尺寸**
   （自动含透视缩放）→ 按优先级排序 → 与已放置矩形相撞的隐藏。
   * 必须在**朝向对齐之后**执行（troika 的 Text 是 Mesh，要先 billboard，顺序反了测出的尺寸会偏）。
   * 优先级按**教学主次**：`CG_LIVE 200 > UI_DYN 110 > T_Zone_* 100 > CARGO_TAG_* 90 >
     Lab_* 80 > TY_* 45 > T* 40`。踩过：把舱区与货舱吊牌放同一优先级时，
     冲突靠相机距离抢位，三个舱区名只保住一个。
   * 单屏可容纳 5~9 条。**这是正确取舍** —— 27 条在任何视角下都不可能都看清。

3. **动态标签内容必须互补**。
   `CG_LIVE`（跟随重心）标重心，`UI_DYN`（座舱上方）标总重/零油重。
   两条都在机身正上方、默认机位下屏幕投影只差约 14 px 必然互相遮挡，
   写同一条信息的话被让掉哪条都等于全丢（实测踩过）。
   实时值一律来自 `refreshLoad()`（与 KPI 同源），不要在 3D 里另算一套。

### 实时标注的两个位移量与实测值
| 元素 | 公式 | 实测 |
|---|---|---|
| `ANNO_CG`（重心标记：CGCone + CGLine） | `CG_DX = (DATUM_X − cg) − CG_BASE` | 后重预设 −1.306 m |
| `YPointer`（横向游标） | `LAT_Z = −1.6 × (cy − CY_BASE)` | 左重预设 +0.919 m |

`1.6` 是**实测放大倍数**：横向标尺把 ±0.5 m 画在 z = ±0.80（`YTick_+05` 的实际位置），
游标必须按同一比例移动，否则会脱标。
`DATUM_X = 18.785` 是机头尖端的模型 X，站位 st 的模型位置 = `DATUM_X − st`。

> 另：原 40 条标注里有 14 条 `UI_*` 锚在 \|y\| = 14.55 —— 正是已移除的 `HUD_BG` 展示屏
> （Blender Z=+14.5）的位置，且内容是 Blender 阶段 7 的烘焙值。已整体移除，
> 实时数值改由 HTML 面板 + 上述动态标签承担。

### 2. Stage 2c 新增的坑（★ 都实际踩过）
1. **Shell_Upper 压风挡区**：上壳体顶弧板外浮 0.02、横跨 ±27°，正好盖住整个风挡带。
   任何外浮 ≤0.02 的贴面层（黑基底/框带）都会被白壳体埋掉，表现为"白眼圈/白楔"。
   → 风挡区贴面层统一 ≥0.024、层间距 ≥4mm（抗 Draco 量化抖动）。
2. **web/groups.json 版本漂移**：dev 页与 standalone 内联的 groups.json 不是同一份，
   旧版缺 `mg_station/ng_station/nose_load_max` → `applyParkTip` 每帧 `toFixed` 崩渲染循环。
   → 重跑 `scripts/export_groups.py` 同步 + 数据守卫（缺字段只复位姿态不抛错）。
   **教训：groups.json 有两份（stage1/ 与 web/），改字段必须两边同步。**
3. **材质覆写必须按材质名 + Map 缓存**：traverse 时逐对象新建材质会让视图侧
   按 uuid 分桶 → draw call 暴涨。按材质名覆写一次并缓存。
4. **微扁旋成体 + 圆环贴面不可共存**：短舱下腹压缩后，按正圆生成的环带/刻线会悬空。
   贴面件要么用同一套变换生成，要么别做。
5. **项目目录搬迁**：`stage1_export.py` 的 ROOT 曾硬编码旧路径，已改为按脚本位置推导
   （`dirname(dirname(abspath(__file__)))`），搬迁项目不用再改。
