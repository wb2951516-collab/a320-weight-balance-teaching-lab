# GLB 元数据契约 v1 · 配载教学建模 Stage 1

> 目的：把 Blender 里的教学语义（拆解组、装配锚点、爆炸方向、舱位归属）完整、无损地送到
> Three.js，使**几何可以随时替换**而动画与交互逻辑不用改。
>
> 本契约是 Stage 1 与 Stage 2 之间的接口。Stage 2 精修几何时**只允许改几何**，
> 不允许改名、不允许改 extras 字段语义。

---

## 一、三条硬规则

1. **物体名冻结。** 对象名（`Seat_0C_21_0`、`Box_FWD_0`、`E_LN` …）原样保留，作唯一追溯键。
   所有语义放 extras，不靠解析名字。
2. **extras 是唯一语义载体。** 导出必须带 `export_extras=True`；缺 extras 的节点视为契约违约。
3. **覆盖 100%。** 每个参与渲染的节点都必须带 `lb_group`。允许出现零覆盖的只有
   `ENV_*`（环境）与 `ANNO_*`（标注）两族，且它们本身也是显式分组。

## 二、坐标与单位

| 项 | 约定 |
|---|---|
| 源坐标系 | Blender **Z-up**，机头朝 **+X**（`NOSE_X ≈ 19.96 m`），尾朝 −X，**左为 −Y** |
| 站位 | `FS = 0` 在机头（DATUM）；`station = NOSE_X − x` |
| 导出 | `export_yup=True` |
| 单位 | 米（`unit_settings.scale_length = 1.0`） |
| 重量/力矩 | kg、kg·m（不随几何变化） |

**导出后的实际朝向（2026-09-22 Stage 1 实测，勿凭经验假设）：**

Blender 轴 → glTF 轴 的映射为 `(x, y, z) → (x, z, −y)`，因此：

| 语义 | Blender | Three.js | 实测证据 |
|---|---|---|---|
| 机身长度轴 | X（37.57 m） | **X** | `HULL_UPPER` bounding box 尺寸 = 37.57 × 4.22 × 4.00 |
| 高度轴 | Z（9.95 m） | **Y** | 机体总盒 Y = 9.95 |
| 展向轴 | Y（34.10 m） | **Z** | 机体总盒 Z = 34.57 |
| **机头方向** | +X | **+X** | 前客舱 `PAX_0A` 中心 X = +5.94、后客舱 `PAX_0C` = −7.89；前货舱 `CARGO_1` = +5.88、散货舱 `CARGO_5` = −10.01；前起落架 `GEAR_N` = +13.01 |

> ⚠️ **机头朝 +X，不是 −Z。** 曾按"Blender 前向导出为 −Z"的常见经验写成 −Z，实测推翻。

**方向向量与锚点仍存 Blender 系**（`extras` 不随导出变换，两者保持一致）。
视图侧加载时用一次变换统一转换，避免混用：

```js
// Blender (x, y, z) -> Three.js (x, z, -y)
const b2g = (v) => [v[0], v[2], -v[1]];
node.userData.lb_dir_three = b2g(node.userData.lb_dir);
node.userData.lb_anchor_three = b2g(node.userData.lb_anchor);
```


## 三、extras 字段表

三个字段族：`lb_*`（本契约新增，强制）、`gx/gy/gz`+`ax/ay/az`（沿用现有，兼容）、`zone/row`（座椅专用）。

| 字段 | 类型 | 必需 | 含义 |
|---|---|---|---|
| `lb_group` | string | ✅ | 拆解组 ID，见第四节 |
| `lb_layer` | int | ✅ | 拆解波次 0–4，9 = 不参与拆解 |
| `lb_dir` | [x,y,z] | ✅ | 该组的爆炸方向，**单位向量**，Blender 系（Z-up） |
| `lb_anchor` | [x,y,z] | ✅ | 装配态世界坐标（Blender 系），= 现有 `ax/ay/az` |
| `lb_zone` | string | — | 客舱分区 `0A`/`0B`/`0C`；货舱填 `HOLD_1`/`HOLD_3`/`HOLD_4`/`HOLD_5` |
| `lb_row` | int | — | 座椅排号 |
| `lb_role` | string | ✅ | `structure`/`payload`/`system`/`annotation`/`env` |
| `lb_src` | string | ✅ | 来源根：`AC_ROOT`（教学装配体）或 `AIRCRAFT_ROOT`（外观壳） |

> `lb_anchor` 与 `lb_dir` 用数组而非 `gx/gy/gz` 三个散字段，避免与既有 prop 混淆；
> 同时**保留**旧字段以免破坏 Stage 0 已发布的测量基线。

## 六、导出参数（Stage 1 固定）

```python
export_format="GLB"

export_draco_texcoord_quantization = 12
```

## 七、验收断言（脚本自动校验，任一不过即失败）

1. GLB 内**所有渲染节点**都有 `lb_group` 与 `lb_layer`。
2. 文字物体（`ANNO_*`）**不产生几何顶点**——Stage 1 保留在 GLB 内但独立成层，交付版由视图侧用
   canvas/SDF 重新出字（See §八）。
3. 拆解组数 ≥ 12（P1 档要求）。
4. 压缩后 GLB ≤ 3 MB（纯几何，不含标注层）。
5. 唯一几何数 ≤ 60（可实例化）。
6. `lb_dir` 全部是单位向量（模长 1±0.01）。

## 八、标注层的处理（P1 硬指标）

Stage 0 实测：40 个文字物体占**求值后顶点的 78.3%**、原 GLB 体积的 **50.4%**
（单个 `UI_DYN` 就吃 10,344 顶点）。因此文字**不出现在交付 GLB 里**。

契约做法（Stage 1 已落地）：

| 产物 | 内容 |
|---|---|
| `teach_model.glb` | **纯几何**，40 个文字物体在导出前从场景移除；`ANNO_CG`/`ANNO_SCALE` 这类**标尺几何保留**（真 3D 物件） |
| `labels.json` | 40 条标注：`{name, text, anchor, size, dynamic, src}`，视图侧用 canvas 贴图或 CSS2D 重建 |

`labels.json` 字段：

| 字段 | 含义 |
|---|---|
| `name` | 原文字对象名（与 .blend 一致，便于追溯） |
| `text` | 文字内容 |
| `anchor` | 锚点，Blender 系（Z-up，m） |
| `size` | 原字号（m），用于换算视图侧像素大小 |
| `dynamic` | `true` = 随装载实时变化（`UI_DYN`/`UI_MAC`/`UI_F1..F3`/`UI_Y`/`UI_PAX`/`UI_ZWF` 等），视图侧需接计算函数重绘 |
| `src` | 来源根 `AC_ROOT` / `AIRCRAFT_ROOT` |

**实测效果**：GLB 内文字几何顶点 **0**；未压缩体积 9.76 MB → 4.95 MB，
Draco 压缩后 **1.58 MB**（压缩比 3.1×），达成 P1 的 ≤3 MB 指标。

## 十、契约 v2 · 自下而上的分层爆炸（2026-09-22）

### 为什么改
v1 的分波是「轴向四波」（货舱向下 / 座椅向上 / 机翼侧向 / 发动机前向）——
方向都对，但**没有先后顺序**，拆解时所有部件近乎同时炸开，观感上没有叙事。
用户要求「爆炸拆解要从下到上，充分展示各结构，速度不要太快」，因此改为
**按高度自下而上逐层剥离**。

### 波次定义（`lb_layer` 语义变更）

| layer | 内容 | 方向（Blender 系） | 位移 |
|---|---|---|---|
| **0** | 标注与环境，**不参与拆解** | — | 0 |
| 1 | 起落架（前/主/轮） | ↓ (0,0,−1) | 7.0 m |
| 2 | 腹板 / 下壳体 | ↓ | 5.5 m |
| 3 | 货舱 1/3/5 + 行李 | ↓ | 4.5 m |
| 4 | 货舱地板 | ↓ | 3.2 m |
| 5 | 客舱地板 | ↓ | 2.0 m |
| 6 | 客舱座椅 0A/0B/0C（186 座） | ↑ (0,0,+1) | 3.0 m |
| 7 | 上壳体 | ↑ | 6.5 m |
| 8 | 机翼（含翼尖小翼） | 侧向外 | 9.0 m |
| 9 | 燃油（左翼/右翼/中央） | 侧向外 / 下 | 6.0 m |
| 10 | 发动机 + 吊挂 | 侧前 (0.6,∓0.8,0) | 7.0 m |
| 11 | 平尾 / 垂尾 | 后向外 (−1,0,0) | 6.0 m |
| 12 | 舱门 / 舷窗 / 标识 | 法向外 | 2.0 m |

> **layer 0 取代 v1 的 layer 9** 表示「不拆解」——v2 波次扩展到 12，必须换一个不冲突的值。
> 读到 v1 数据（含 layer 9 的标注）时按 0 处理即可。

**1–7 是竖直主干**（这就是「从下到上」）；**8–12 是结构展开段**——
机翼/发动机/尾翼若永不分离，"充分展示各结构"就落空，因此保留为同一滑块的后半段。
用户若要纯竖直效果，只需把 8–12 的窗口删除，无需重做几何。

### 方向的两处关键修正
- **客舱地板 `FLOOR_CABIN`**：v1 是 ↑（"掀起地板"意象），v2 改为 **↓**——
  地板向下让位，客舱与货舱才真正分离，座椅才能干净地整体上抬。
- 其余组的方向沿用 v1（实测与新方案一致），无需变更。

### 节奏（不在契约内，属视图侧参数）
位移距离与时长**不写进 `extras`，留在视图侧**——它们是表现参数，频繁调，
每次调都重跑 Blender 不现实。当前取值：

| 参数 | 值 | 位置 |
|---|---|---|
| 波次窗口 | 每波占 11.5% 进度，相邻重叠 30% | `web/index.html` `LAYER_WINDOW` |
| 每波位移 | 见上表 | `LAYER_AMP` |
| 全拆总时长 | **32 s**（用户要求"不要太快"） | `SECONDS_TOTAL` |
| 层内错峰 | 同波实例按「高度优先、站位其次」排序，启动延时最多占该波窗口 45% | `STAGGER_FRAC` |

> 层内错峰是为了消除此前"整层像一块板刚性平移"的观感短板。

## 九、Stage 1 实测验收结果（2026-09-22，v1 时期）

> 下表的节点数为当时的 697；v2 重建翼面并补到 186 座后为 **711**（见第十节实测）。
| 断言 | 结果 |
|---|---|
| 渲染节点 `lb_group`/`lb_layer`/`lb_dir`/`lb_anchor` 覆盖率 | **697/697 = 100%** PASS |
| 拆解组数（非标注/环境） | **29 组**（要求 ≥12） PASS |
| GLB 内文字几何顶点 | **0** PASS |
| `lb_dir` 单位向量 | 异常 0 PASS |
| 压缩后 GLB ≤ 3 MB | **1.58 MB** PASS |
| Three.js r186 加载 + extras 全量保留 | PASS（Node 无头验证） |
| 场景级阶段表随导出保留 | PASS（40 个键，含 `lb_stage_0..6`） |
| 座椅 zone/row 缺口修复 | **补齐 360 件**（原靠背/头枕全缺） |

**几何复用实测**：Three.js 侧按顶点位置哈希去重得 **52 种唯一几何**
（与 Blender 侧局部坐标签名结果完全一致，双向交叉验证）。
因此 `InstancedMesh` 可把 draw call 从 **697 降到 52**（省 645）。

> ⚠️ **去重不是自动的**：GLB 往返后每个物件拿到独立 `BufferGeometry`，
> **必须在视图侧显式按几何签名合并再建 InstancedMesh**，否则 697 次 draw call 一次也省不掉。

**波次分布实测**：layer 1 = 101 个、layer 2 = 5、layer 3 = 2、layer 4 = 571、layer 9 = 18。

**Stage 1 的已知空组**（Stage 2 填充）：`HULL_LOWER`、`CARGO_4`、`GEAR_WHEEL` 之外的
真实轮组、以及 P1 要求的翼肋/桁条/框骨架。
